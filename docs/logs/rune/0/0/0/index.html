Change Log — MCIdentityRune 0.0.0

Permalink for MCIdentityRune version 0.0.0.

0.0.0 2026-07-31 · Initial release

The first release of MCIdentityRune, the standalone rune add-on for MCIdentity. Every identity gets its own rune slots, stored in the add-on's own database and opened with /rune.

Added Rune slots keyed by identity

  • Ten slots per identity, the last reserved for the ultimate rune. The slot numbering is stored, so the menu layout is fixed and existing rows keep their meaning.
  • Every read and write is tied to the identity MCIdentity says the player is wearing, never to the player. Two identities owned by one player wear entirely separate runes.
  • The identity is resolved once at the start of an interaction, so a player who swaps identity mid-action cannot write to the identity they just left.
  • Reads fail closed: an unresolvable identity or an unreachable core plugin yields an empty result, never another identity's runes.

Added Its own storage

  • The list of rune types and every identity's slot assignments are created and owned by this add-on, with no link to anything MCIdentity stores.
  • Backends: SQLite (default, zero configuration), MySQL, PostgreSQL, MongoDB, or the shared central server, chosen in the add-on's configuration file.
  • Schema creation is idempotent and runs on every start. Every query binds its parameters; the only identifiers ever interpolated come from a frozen allow-list.
  • All database work runs off the game thread on the add-on's own worker pool.

Added Menu, commands, and developer API

  • /rune opens the six-row rune menu for the identity you are wearing. /rune list lists registered rune types.
  • /rune register <code> <display name>, /rune set <slot> <code>, and /rune clear <slot> require mcidentityrune.admin.
  • A cancellable rune set event, telling listeners the player, the identity, the slot, and the rune (none when clearing).
  • A published developer library in three modules, matching the core plugin's shape.

Note Requirements

  • One universal jar for SpigotMC, PaperMC, and Folia; the server type is detected at startup.
  • MCIdentity 4.0.0 or newer is a hard dependency — that is the release where the core stopped shipping a rune system of its own. An older core logs a warning at startup, because the two rune systems would sit side by side.
  • The base player profession may not equip runes. Cosmetics carry no such restriction — see MCIdentityCosmetic.
  • Rune assignments from MCIdentity 3.x are not migrated. The core drops its own tables on upgrade and this add-on starts empty.
