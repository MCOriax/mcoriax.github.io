0.3.0 Latest 2026-08-03 · A skill is held once

An identity may now hold a given skill in at most one slot. Equipping a skill it already has equipped elsewhere is refused, so the slots are a set of distinct skills rather than somewhere to stack one skill for extra effect.

Added A skill is held once

  • Equipping a skill the identity already holds in another slot is refused, in the menu and through /skill equip alike. The refusal names the reason rather than looking like a failed click.
  • The check reads the skill code out of each filled slot's item. The item is where a skill's code lives and no column records it, so nothing was added to storage — the rows and the items cannot drift apart.
  • Codes are compared trimmed and lower-cased. A code is a MythicMobs ID typed by hand into /skill give, so Quarry_Sense and quarry_sense are one skill; treating them as two would let the rule be sidestepped with the shift key.

Note When a slot cannot be read

  • A filled slot whose item cannot be decoded refuses the equip. Its code is unknowable, so allowing would assert the slots differ without having checked, and a restriction that cannot be proved denies.
  • The practical cost: one corrupt row blocks equipping for that identity until an administrator clears that slot. The alternative — letting an unreadable slot pass silently — is worse.

Note For server owners and integrators

  • Nothing is rewritten. An identity that already holds the same skill in two slots keeps both. The rule applies to new equips only.
  • Slot permanence is unchanged and was already enforced: a filled slot has never been replaceable.
  • No item format change and no schema change. Skill items already in players' inventories carry the same data and keep working.
  • Library coordinates move with the release: io.github.mcoriax:mcidentity-skill-api:0.3.0, -common:0.3.0, and -bukkit:0.3.0. A plugin constructing the equip service directly now passes the item codec to it.
