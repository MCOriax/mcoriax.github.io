Change Log — 0.2.0

Permalink for MCIdentitySkill version 0.2.0.

0.2.0 2026-08-03 · One command for players

A player now has one command. /skill opens their skill menu, equipping happens inside that menu, and every subcommand became an operator's. There is nothing else for a player to learn.

Changed /skill opens the menu

  • A bare /skill now opens the skill menu of the identity you are wearing. It previously printed a list of subcommands.
  • /skill gui is gone. The bare command replaces it, so a player has no argument to remember.
  • The base player identity still has no menu, and /skill refuses for it and says which fix applies: wear an identity with a profession first.

Added Equipping happens in the menu

  • Hold a skill item and click an empty slot in the menu to equip it there. That one action is the whole of what a player does with this add-on.
  • The menu is redrawn from storage after a successful equip, so the slot shows the skill it now holds.
  • Clicking a slot with nothing relevant in hand explains what the slot is instead of looking like a failed click.
  • Every rule is unchanged and still decided in one place: an occupied slot is refused because an equipped skill is permanent, and the base player identity and a missing identity are refused exactly as they were.

Changed Every subcommand is an operator's

  • /skill info and /skill equip <slot> now default to op. /skill give and /skill clear already did.
  • All four sit under mcoriax.mcidentity.skill.admin, so one node grants the administrative surface.
  • mcoriax.mcidentity.skill.command.gui is now the only node granted to everyone — it opens the menu, and it is the whole of what a player holds.
  • Tab completion returns nothing without the admin node, and the usage summary lists the subcommands only to a sender who can run them.
  • /skill equip <slot> stays as an administrative command for the cases a click cannot cover. It obeys the same rules and still has no inverse.

Note For server owners

  • Re-check your permissions. A server that granted mcoriax.mcidentity.skill.command.info or .command.equip to players explicitly keeps granting them. A server relying on the old defaults loses them for players, which is the intent.
  • Update any /skill gui you have written down. A command block, sign, NPC, or menu plugin pointing at it must now point at /skill.
  • Nothing about the item changed. Skill items already in players' inventories carry the same data and keep working.
  • Library coordinates move with the release: io.github.mcoriax:mcidentity-skill-api:0.2.0, -common:0.2.0, and -bukkit:0.2.0.
