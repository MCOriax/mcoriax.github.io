Change Log — 0.1.0

Permalink for MCIdentitySkill version 0.1.0.

0.1.0 2026-08-02 · Base identity lock

The base player identity every player starts with now owns no skills at all. It cannot equip or use a skill item, and it has no skill menu. Skills belong to a chosen profession, so a player picks one first.

Changed The base player identity owns no skills

  • player is the reserved profession of the base identity. It is now the one profession that never matches a skill item — previously it was treated like any other profession.
  • While the base identity is worn, a skill item cannot be equipped or used whatever profession it asks for. The refusal applies everywhere the restriction already applied: inventory click, drag, hotbar selection, and right-click use.
  • An item stamped with the profession player does not work around it. The base identity is answered before the two professions are compared, so no item can be built that grants it a skill.
  • The denial has its own message, so a player is told what to do rather than only that they were refused:
    [Skill] Your base player identity has no skills. Wear an identity with a profession to use one.

Changed The skill menu belongs to a profession

  • /skill gui no longer opens for the base identity — it has no slots to show, and the refusal happens before any storage is read.
  • /skill equip <slot> refuses for the base identity as well, so nothing can be written to a slot it does not own.
  • Both refusals name the base identity and point at the fix: wear an identity with a profession first.

Note For integrators

  • The access check reports a new outcome, BASE_PROFESSION, alongside the existing ones. Code that treats anything other than the allowing outcome as a denial needs no change; a listener that switches on the outcome by name may want a branch for it.
  • Library coordinates move with the release: io.github.mcoriax:mcidentity-skill-api:0.1.0, -common:0.1.0, and -bukkit:0.1.0.
  • Nothing else changed: the item is still the record, the restriction still fails closed and cannot be switched off, and an equipped skill is still permanent.
