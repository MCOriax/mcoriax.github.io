Change Log — 3.0.0

Permalink for version 3.0.0.

3.0.0 Archived 2026-07-28 · Skill decoupling

Skills leave the core plugin. MCIdentity now focuses purely on identity, stats, and session management, and the skill system ships separately as MCIdentitySkill — where a skill's data lives on the item instead of in the database.

⚠️

Back your database up before upgrading. The first start after this update drops the two ability tables and their rows are not recoverable.

Changed Skills moved to a standalone add-on

  • The ability system was removed from this plugin. Profession restricted skill items now live in MCIdentitySkill, a separate jar installed alongside this one.
  • The new add-on stores a skill's data in the item's Persistent Data Container rather than in a table, so a skill item carries its own skill ID and profession wherever it goes.
  • Nothing about identities, professions, stats, cosmetics, runes, or sessions changed. Those still live in your chosen storage backend exactly as before.

Removed Database tables

  • identity_abilities and identity_equipped_abilities are no longer created, and are dropped on the first start after upgrading. On MongoDB the identity_abilities collection is dropped and the per-identity equipped_abilities field is unset.
  • The central server drops the same two tables on startup; its /v1/abilities and /v1/identities/:uuid/abilities endpoints now answer 404.

Removed Commands, GUI, and permissions

  • /identity ability get and /identity ability create are gone, along with their tab completion. Use /skill give from the add-on instead.
  • The Ability GUI and its button in slot 2 of the main identity menu were removed. The Rune and Cosmetic GUIs are unchanged.
  • The gui.buttons.ability entry in textures.yml is no longer read and can be deleted.

Removed Developer API surface

  • Dropped from MCIdentityProvider: createAbility, getAbilities, getEquippedAbilities, and setEquippedAbility.
  • Deleted model types: Ability and EquippedAbility. ActiveIdentitySession no longer carries an equipped abilities map, so its constructor takes one fewer argument.
  • Deleted event: IdentityAbilitySetEvent. The add-on fires its own MCIdentitySkillEquipEvent and MCIdentitySkillUseEvent.
  • Integrating plugins that used any of these must depend on MCIdentitySkill and move to its API. Everything else in the provider is source-compatible with 2.0.0.

Note Server owners

  • Install MCIdentitySkill alongside this plugin if you use skills. It requires both MCIdentity and MythicMobs, and refuses to enable without them.
  • Existing ability items stop working — the add-on reads its own persistent data keys, not the old ones. Re-issue them with /skill give.
