Change Log — 4.2.0

Permalink for version 4.2.0.

4.2.0 2026-08-02 · One way in

MCIdentity now has exactly two supported entry points, and only two: MCIdentityProvider for everything that is stored, and MCIdentityManager for everything held in memory. Nothing changes for server owners; integrating plugins get a smaller, clearer surface to write against.

ℹ️

Server owners can upgrade straight in. There is no schema change, no configuration change, and no data migration in this release. Drop the new jar in and restart.

Changed The storage backend is no longer handed out

  • MCIdentityProvider keeps its storage backend to itself. There is no supported way to obtain the raw persistence contract, or one of the concrete backends behind it, and call it directly.
  • Everything the backend can do is reachable on the provider instead — reads, writes, and the storage lifecycle. If something you need is missing from it, treat that as a gap worth reporting rather than a reason to reach around it.
  • Storage is brought up with MCIdentityProvider.create(type, options), which builds the backend and installs it as MCIdentityProvider.instance.
  • See Developer API for the full provider reference.

Changed MCIdentityManager is RAM state only

  • MCIdentityManager now covers exactly one job: state held in memory — active identity sessions, profession configuration, and per-player gameplay state.
  • Anything that touches the database moved to MCIdentityProvider. The split means a call site no longer has to know which of the two facades happens to own a given operation: if it is stored, it is on the provider.

Note Deprecation

  • MCIdentityManager.createDatabase(...) is deprecated, because it returned a raw backend. It still works in this release.
  • Move any code that called it to MCIdentityProvider.create(type, options), which builds the same backend and makes it the active provider.
  • Server owners are unaffected either way — the plugin wires its own storage from config.yml and never went through that method.

Note Compatibility

  • No gameplay, command, permission, GUI, or configuration behaviour changes in this release.
  • The MCIdentitySkill, MCIdentityRune, and MCIdentityCosmetic add-ons are unaffected: each owns its own storage and reads the equipped identity through the session cache, which is unchanged.
  • Every supported backend — SQLite, MySQL, MariaDB, PostgreSQL, MongoDB, and the central server — keeps working exactly as before. See Data Storage.
