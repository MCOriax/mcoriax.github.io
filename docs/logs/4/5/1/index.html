Change Log — 4.5.1

Permalink for version 4.5.1.

4.5.1 Latest 2026-08-02 · The item keeps up

A follow-up to 4.5.0. The alias naming introduced there reached the item only on a level up, so claiming a name left your identity item titled with its old one until you next levelled. It is now re-titled the moment the alias is.

Fixed Claiming an alias re-titles the item

  • /identity alias <name> renamed you in chat and in the tab list straight away, but left the identity item itself on its previous title until the next level up. The item is now rebuilt as soon as the name is claimed.
  • The Main Identity GUI shows the same stored item in its identity slot, so it picks up the new title at the same moment.

Fixed Older items catch up when equipped

  • An identity item created before 4.5.0 kept its old [Profession] [Level] title indefinitely, because nothing rebuilt it apart from a level up.
  • An identity item is now rebuilt whenever the identity is equipped, so every item in circulation is brought up to date simply by being worn.
  • This is what 4.5.0's release note described but did not actually do; that note has been corrected.

Note Unchanged

  • The presentation itself is exactly as 4.5.0 defined it: the alias as the title, the profession and level in the lore, and the profession name standing in until an alias is claimed. See GUI System and Key Features.
  • Identities are still recognised by their persistent data alone. Renaming an identity item or clearing its lore breaks nothing — the text is simply rewritten the next time the identity is rendered, which now happens rather sooner.
  • Alternative identity heads in the Player Identity GUI were never affected: they are built from stored data every time the menu opens.

Note Server owners

  • Drop the new jar in and restart. No schema change, no configuration change, and nothing to migrate on any backend, the central server included.
  • Behaviour is identical on SpigotMC, PaperMC, and Folia.
  • Equipping an identity now performs one additional background write to keep the stored item and the session in step. It happens once per equip.
