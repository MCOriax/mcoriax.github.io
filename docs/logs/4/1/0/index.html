Change Log — 4.1.0

Permalink for version 4.1.0.

4.1.0 Latest 2026-08-02 · Identity aliases

Every identity can now carry a name of its own. /identity alias <name> claims one for the identity you are wearing: alphanumeric only, unique across the whole server, and matched without regard to capitalisation, while the name is stored exactly as you typed it.

ℹ️

Nothing is deleted by this update. Identities gain an alias field on the first start after upgrading, and every existing identity simply starts without an alias. No backup dance is required this time.

Added The /identity alias command

  • /identity alias shows the alias of the identity you are currently wearing, or tells you how to claim one when it has none.
  • /identity alias <name> claims that name. Running it again renames the identity, and a name you give up becomes available to everyone else.
  • A name may contain letters and digits only (a-z, A-Z, 0-9) and at most 32 of them. Spaces, underscores, hyphens, and symbols are rejected with a message explaining the rule.
  • An alias is unique across every identity on the server, and the check ignores case: once someone holds Alex, both alex and ALEX are refused for everyone else. Your own capitalisation is preserved, so Alex is shown as Alex.
  • Available to all players by default, under the new mcoriax.mcidentity.command.alias permission. Tab completion lists the sub-command and hints at the argument.
  • See Commands & Permissions for the full reference.

Added The alias column

  • Every identity gains an optional alias field.
  • Every backend enforces the same rule its own way: a unique index over the folded value on SQLite and PostgreSQL, a case-insensitive collation on MySQL and MariaDB, a sparse unique index on MongoDB, and the server's own check — answering 409 Conflict — on the central server.
  • A database created before this release gains the field automatically on the next start.
  • See Data Storage for the column reference and the per-backend details.

Added Developer API

  • The provider can now find the identity holding an alias, in any capitalisation, and can claim or release an alias. A claim is refused when the name is malformed or already taken.
  • An identity's alias now comes back with every read of its properties.
  • See Developer API for the usage reference.

Changed Property writes

  • An alias is claimed through its own operation rather than through a general property update, so the uniqueness check and the write always happen together and two identities can never end up sharing a name.
  • Because of that, updateProperties deliberately leaves the alias alone: it can neither bypass the check nor clear someone's name by leaving the field out.
  • Plugins that build identity properties themselves now supply an alias as well; supplying none keeps the previous behaviour.

Note Server owners

  • If you store data on the central server, update the MCIdentity central server to 3.3.0 or newer as well — that is the release where it learned the alias endpoints. On any other backend nothing outside the plugin has to change.
  • Aliases are purely a naming feature: they do not affect professions, stats, sessions, or any add-on.
