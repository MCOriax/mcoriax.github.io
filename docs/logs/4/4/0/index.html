Change Log — 4.4.0

Permalink for version 4.4.0.

4.4.0 Latest 2026-08-02 · A name you keep

An alias becomes something you settle on rather than something you swap. A name is claimed once and kept for the life of the identity, and the base Player identity steps out of the system entirely — it is your own character, so it always goes by your Minecraft name.

⚠️

This changes what /identity alias allows. Up to 4.3.1 a player could run the command again to rename an identity. They no longer can. Nothing stored is altered by upgrading — every alias already claimed stays exactly as it is — but tell your players to choose deliberately, because the name sticks.

Changed An alias is claimed once

  • Running /identity alias <name> on an identity that already carries an alias is refused with "This identity alias is already set as ...", and the name already claimed is left untouched.
  • Claiming a name on an identity that has none works exactly as before, including the alphanumeric rule, the 32 character limit, and the server-wide uniqueness check that ignores capitalisation.
  • /identity alias with no arguments still reports the current alias.
  • Because a name is never released, one that is taken now stays taken. See Commands & Permissions for the full reference.

Changed The base Player identity keeps your Minecraft name

  • The base player profession is your own character rather than a role you put on, so it is never renamed. Chat and the tab list show your Minecraft name, as [Player] Steve.
  • /identity alias <name> is refused on that identity, and /identity alias reports that it always goes by your Minecraft name instead of offering to claim one.
  • Alternative base identities are not affected. They carry ordinary professions rather than the reserved player one, so they claim and show aliases like any other identity.
  • If an earlier release let someone put an alias on their base identity, that value is simply no longer shown. It is not deleted, so nothing is lost.

Note Developers

  • MCIdentityProvider.setIdentityAlias(UUID, String) is unchanged and still renames an identity or releases its name with null. Both new rules live in the /identity alias command, not in the provider or the database column.
  • That leaves the door open for an administrative tool or an integrating plugin to correct a name a player cannot change themselves.
  • See Developer API for the provider reference and Data Storage for the alias column.

Note Server owners

  • Drop the new jar in and restart. No schema change, no configuration change, and nothing to migrate on any backend, the central server included.
  • Behaviour is identical on SpigotMC, PaperMC, and Folia.
  • Professions, stats, sessions, and every add-on are untouched by this release.
