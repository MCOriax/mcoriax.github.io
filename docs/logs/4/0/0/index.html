Change Log — 4.0.0

Permalink for version 4.0.0.

4.0.0 2026-07-31 · Rune and cosmetic decoupling

Runes and cosmetics leave the core plugin, completing the split that started with skills in 3.0.0. MCIdentity now owns identity, stats, and session management and nothing else; runes ship as MCIdentityRune and skins and auras as MCIdentityCosmetic, each with its own storage.

⚠️

Back your database up before upgrading. The first start after this update drops the rune and cosmetic tables. The add-ons start with empty tables rather than migrating them, so existing rune assignments, skins, and auras are not recoverable.

Changed Runes and cosmetics moved to standalone add-ons

  • Runes now live in MCIdentityRune and skins and auras in MCIdentityCosmetic — separate jars installed alongside this one, each on its own version line.
  • Each add-on creates and owns its own data, stored against the identity, with no link to anything this plugin stores. Either side can be upgraded, or backed by a different database, without waiting for the other.
  • Each add-on decides its own profession rules: MCIdentityRune blocks the base player profession from equipping runes, while MCIdentityCosmetic allows every profession, base included.
  • Nothing about identities, professions, stats, or sessions changed. Those still live in your chosen storage backend exactly as before.

Removed Database tables

  • The rune and cosmetic data is no longer created, and is deleted on the first start after upgrading, on every backend including MongoDB.
  • The central server drops the same tables on startup; its /v1/runes, /v1/identities/:uuid/runes, and /v1/identities/:uuid/cosmetics endpoints now answer 404.

Removed Commands, GUI, and resources

  • /identity rune get is gone, along with its tab completion and its line in the admin help. Use /rune from the add-on instead.
  • The Rune GUI and Cosmetic GUI and their buttons in slots 6 and 8 of the main identity menu were removed. The add-ons open their own menus with /rune and /cosmetic.
  • The rune and cosmetic button textures in the menu texture file are no longer read and can be deleted.

Removed Developer API surface

  • The provider no longer offers any way to list or set runes, or to read or save skins and auras.
  • The rune data type is gone, and an identity's properties no longer include a skin or an aura.
  • The rune, skin, and aura set events are gone. The add-ons fire their own rune set and cosmetic set events.
  • Integrating plugins that used any of these must depend on the relevant add-on and move to its API. Everything else in the provider is source-compatible with 3.0.0.

Note Server owners

  • Install MCIdentityRune and MCIdentityCosmetic alongside this plugin if you use either feature. Both require MCIdentity 4.0.0 or newer.
  • Each add-on has its own configuration file with its own storage settings, and each defaults to a local SQLite file. They do not have to share a backend with this plugin, or with each other.
  • Both add-ons ship switched off, so the first start writes the configuration file and stops there. Switch the add-on on and restart.
