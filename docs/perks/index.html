Add-on plugin · MCIdentityPerks

Every identity grows in its own way.

MCIdentityPerks is an add-on that gives each MCIdentity identity deep progression of its own: a permanent Sigil, a set of equippable Relics, and Perks that level up over time. Like the other add-ons, it ships as its own jar, keeps its own database, and installs alongside the core plugin.

🚧

Not released yet. MCIdentityPerks is in early development. Its design and documentation are in place, but the plugin itself cannot be installed yet. This page describes what it is being built to do.

Three ways to build a character

🜂
Sigils

A permanent symbol an identity pledges itself to, such as one of the seven deadly sins or the seven heavenly virtues. An identity may choose exactly one, and the choice can never be undone or swapped, so the plugin asks the player to confirm before saving it.

🗝️
Relics

Artifacts placed into numbered slots to mix and match their effects. An identity can wear several Relics, but never the same one twice. Placing a Relic into a filled slot replaces what was there, and the number of slots is set by the server owner.

⬆️
Perks

Passive traits that are unlocked once and then levelled up, usually for Gold and themed items, to permanently increase an identity's power or usefulness.

It belongs to the identity, not the player

There is no such thing as "this player's perks", only "this identity's perks".

MCIdentity stays in charge of identities, stats, and sessions. This add-on only asks it which identity a player is wearing, and keeps all of its own data against that identity. When a player switches to another identity, their Sigil, Relics, and Perks switch with it completely. Nothing is ever copied between identities, because nothing was ever tied to the player.

Storage

The add-on keeps its own database, so progression survives every relog. It stores the lists of Sigils, Relics, and Perks the server offers, and for each identity its chosen Sigil, its equipped Relics, and its unlocked Perks with their levels.

It never reads or changes the core plugin's data, and nothing in its storage depends on the core plugin's storage. The two plugins can even use different databases, and each can be upgraded without waiting for the other.

Requirements

  • A SpigotMC, PaperMC, or Folia server. One universal jar covers all three.
  • The core MCIdentity plugin, installed and enabled. It is a hard dependency, so the server will not enable this add-on without it.
